## Context

У нас є команда "Cut intercalated structure cell", яка вирізає комірку по X та Y координатах. Ідея такої комірки в тому, щоб отримати мінімальну за розміром комірку, яка шляхом паралельних перенесень дозволяє побудувати всю структуру.

Нам треба також сюди додати 3 речі:

1. Логіку обрізання по Z координаті,
2. Створення файлу `cell_params.txt`,
3. Нове іменування папки результату `cell_{type}_v{i}`.

Приклади результату (зроблені вручну): `data/projects/intercalation_and_sorption/ar/result_data/C2-7_h3/cell_ABAB`, `.../C0-7_h3/cell_ABC`, а також набір `data/projects/intercalation_and_sorption/ar/ar-cells-with-basis/*` (там для A1–A3, B1–B4, C0–C2 є і комірки, і `cell_params.txt`).

## Scope

**Входить:** обрізання по Z, `cell_params.txt`, іменування папки, тести, оновлення інтерфейсів.

**Не входить:**

- Зміна xy-логіки обрізання (призма по 4 центрах каналів): вона вже точно відтворює вуглець референсів C0 і C2.
- Автоматичне транслювання `one_ch` файлу в `all_ch` перед обрізанням.
- Імена `.dat` файлів комірки лишаються як зараз: `{structure_dir}_cell_carbon.dat` та `{structure_dir}_cell_{subproject_dir}_intercalated.dat`.

## Вхідні дані

- Інтеркальовані атоми: файл, вибраний у dropdown (`get_inter_coords`), очікується `all_ch` (див. «Попередження для one_ch»).

## Логіка обрізання по Z координаті

Ми повинні знайти мінімальну висоту комірки `c` таким чином, щоб трансляцією вгору на `c` комбінація атомів вуглецю та інтеркальованих атомів співпала з усіма наступними шарами. Для трансляції беремо одразу і вуглець, і інтеркальовані атоми.

Перевірено на всіх готових комірках з `ar/result_data` та `ar/ar-cells-with-basis`: `c` з `cell_params.txt` завжди дорівнює мінімальному спільному періоду вуглецю й Ar, і він кратний періоду вуглецю `c_C`. Приклади: C0 AA/ABAB `3·c_C = 14.965`, C0 ABC `9·c_C = 44.895`, B2 AA `3·c_C = 7.482` (для B `c_C ≈ 2.494`, тож `c` не завжди кратне 4.988).

### Алгоритм

1. **Період вуглецю `c_C`.** Найменший зсув по Z, що переводить вуглець init-структури сам у себе (допуск 0.1 Å; можна взяти `StructureValidator.find_z_period`). Очікувані значення: A = 4.32, B ≈ 2.494, C ≈ 4.988 (перевірено на всіх 12 структурах `init_data`).
   - **Точне значення.** `find_z_period` повертає період, округлений до 3 знаків (4.988), а справжній `c_C = 4.98831`. Це критично, бо `9·4.988 = 44.892`, а референс має `44.895`. Тому `c_C` треба уточнити з неокруглених координат (наприклад, середній зсув між співпавшими атомами) і округлювати лише при запису у файл.
2. **Кратність `n`.** Найменше ціле `n` (від 1 до 20), для якого інтеркальовані атоми (вже відфільтровані призмою по xy) переходять самі в себе при зсуві на `n·c_C` (допуск 0.1 Å). Так вуглець автоматично теж співпадає. Тоді `c = n·c_C`.
   - Інтеркальовані атоми **не** обрізаються по z-діапазону вуглецю (зараз це робить `z_min..z_max` вуглецю в `cut_unit_cell`; для inter цю обрізку прибрати).
   - Збіг вважається **підтвердженим**, лише якщо в області перекриття оригіналу і зсунутої копії є щонайменше 2 атоми (параметр `min_overlap_atoms`, за замовчуванням 2). Інакше при малому перекритті можна отримати хибний менший `c` (приклад: `final_all_ch-v3-ABC.xlsx` має лише 4 шари; зсув на `2·c_C` перекривається по одному атому й збігся б).
3. **Fallback, якщо підтвердженого повтору немає** (файл коротший за період, приклад: `final_one_ch-v6-ABC-Codex.csv`, один період, z 1.67–42.84). Беремо `c = n_f·c_C`, де `n_f = round((z_max_inter − z_min_inter + d) / c_C)` (мінімум 1), а `d` — медіанний крок між шарами інтеркальованих атомів (якщо шар один, `n_f = 1`). Для v6-ABC: `(41.17 + 3.74) / 4.98831 = 9.0`, `n_f = 9`, `c = 44.895` ✓. У цьому випадку показати користувачу попередження "повтор по z не підтверджено перекриттям" (`GeneralView.show_warning_message`) і записати це в лог.
4. **Вікно по Z.** `z0` = мінімальний z вуглецю init-структури (у всіх init це 0.0). Комірка — це атоми з `z ∈ [z0, z0 + c)`, півінтервал (верхня межа не включається, щоб не дублювати атоми). Інтеркальовані атоми поза вікном відкидаємо (вони еквівалентні трансляціям). Якщо у вікні немає жодного інтеркальованого атома, повідомляємо про помилку.
5. **Вуглець у комірці.** Висота init-вуглецю може бути меншою за `c` (C0/C2 мають z до 14.14, а C0 ABC потребує 44.9). Тому вуглець комірки будуємо так: беремо вуглець з призми по xy в `z ∈ [z0, z0 + c_C)` (один період) і розмножуємо трансляціями `k·c_C`, `k = 0 … n−1`. Для init, де висоти вистачає, результат має збігатися з прямою вибіркою `z ∈ [z0, z0 + c)`.

Очікувані кількості атомів вуглецю в комірці (мають збігатися з референсами): C0 — 16 атомів на період (AA і ABAB: 48, ABC: 144), C2 — 40, A1 — 10.

## Створення файлу `cell_params.txt`

Файл створюється поруч із `.dat` файлами комірки при натисканні на "Cut intercalated structure cell". Кодування UTF-8 (є символи α, β, γ).

### Basis

Усі розміри беруться з init-вуглецю. Вектори беруться з геометрії **одного повного каналу** (будь-якого, можна перший з `split_init_structure_into_separate_channels`):

1. Беремо xy-проєкцію каналу і її опуклу оболонку (convex hull точок каналу).
2. `P1` — лівий кінець нижнього ребра: серед вершин з мінімальним Y беремо ту, що має найменший X. Для більшості структур це `(0, 0)`, але, наприклад, для B1 це `(−4.32, 0)`, а для B2 `(0, −6.043)`.
3. `P2` — вершина з **найбільшим X** (її Y лежить посередині висоти каналу).
4. `(X, Y) = P2 − P1`. Приклад: A1 `(3.993, 2.305)`; B1 `(6.453, 4.786)`.

> Зверни увагу: формулювання "вершина з найбільшим Y" з першої версії задачі не відповідає прикладу (для A1 вершина з найбільшим Y це `(2.662, 4.61)`, а `P2 = (3.993, 2.305)` це найправіша). Правило вище відтворює всі перевірені референси (A1, A2, A3, B1, B2, B3, B4, C0, C2; для A1.5, A2.5, C1 збіг перевірено орієнтовно).

Вектори базису (як у наявних файлах):

- `a = (−X, Y, 0)`
- `b = (X, Y, 0)`
- `c = (0, 0, c)`, де `c` — висота комірки з попереднього розділу.

Порядок `a`/`b` у файлах-референсах саме такий (у першій версії задачі було навпаки), тому дотримуємось файлів.

### Параметри

- `a = |(X, Y)| = sqrt(X² + Y²)`.
- Гексагональна гратка (структури A* і C*): `X / Y = √3` (перевіряємо з допуском 0.01). Тоді пишемо лише `a=` і `c=`.
- Інакше (структури B*): додатково `α=β=90` і `γ`, а замість `a=` пишемо `a=b=`.
- `γ` = кут між записаними векторами `a` і `b` (тупий кут): `γ = degrees(acos((Y² − X²) / (X² + Y²)))`. Це рівно `180 − ∠BFD` з формули в первісній задачі:
  $$\angle BFD = 2 \arctan\left(\frac{a \sin\alpha}{b - a \cos\alpha}\right)$$
  Рахуємо з неокруглених координат, а не з округлених сторін (з округлених `a=5.86`, `b=3.07`, `α=125.3` вийде 107.0). Для B1 це дає 106.84 проти 106.87 у файлі, тож в тестах допуск 0.05°. У референсах B3 `cell_ABAB_1/_2` (47.907) і B4 (49.587) значення γ — гострий кут (`∠BFD`), це вважаємо застарілим форматуванням і не відтворюємо.

### Формат

Числа з 3 знаками після коми, зайві нулі в кінці прибираємо (`4.61`, `14.18`, `106.87`, компонент нуль пишемо `0`). Перевірено, що так відтворюються всі референси.

Для A* і C*:

```
a=4.61
c=4.32

Basis:
a = (-3.993, 2.305, 0)
b = (3.993, 2.305, 0)
c = (0, 0, 4.32)
```

Для B*:

```
α=β=90
γ=106.87

a=b=8.034
c=4.988

Basis:
a = (-6.453, 4.786, 0)
b = (6.453, 4.786, 0)
c = (0, 0, 4.988)
```

Ім'я файлу — `cell_params.txt` (у деяких старих папок `cell_params_.txt`, це ручні варіанти).

## Іменування папки результату

Замість `cell_{type}` (зараз) — `cell_{type}_v{i}`. Приклад: з `final_one_ch-polygon-ABAB-v3.csv` (або `final_all_ch-polygon-ABAB-v3.csv`) виходить `cell_ABAB_v3`.

### Парсинг імені вибраного файлу

Беремо ім'я файлу без папки й розширення, ділимо за `-`:

- `i` — перший токен виду `v<число>` (`final_one_ch-polygon-ABAB-v3` → 3; `final_one_ch-v6-ABC-Codex` → 6).
- `type` — перший токен, що повністю складається з літер A–D довжиною ≥ 2 (`ABAB`, `AA`, `ABC`, `ABCD`). Токени `Codex`, `Claude`, `NV` ним не стають.
- База імені: `cell` + (`_{type}`, якщо знайдено) + (`_v{i}`, якщо знайдено). Тобто `final_all_ch-v1.xlsx` → `cell_v1`, `final_one_ch-v2-Claude.xlsx` → `cell_v2`, а якщо немає ні типу, ні версії → `cell`.
- Старий `_get_structure_type_from_file_name` розраховує на пробіли в імені файлу (формат, якого вже немає), тому для нових імен завжди повертає `cell`. Його замінити.

### Колізії

Якщо папка з такою базою вже існує, нічого не перезаписуємо, а створюємо `{база}_{j}`, де `j = 1, 2, …` — перше вільне (`cell_ABAB_v3` існує → `cell_ABAB_v3_1`, потім `cell_ABAB_v3_2`). Створювати папку через `mkdir(exist_ok=False)`.
